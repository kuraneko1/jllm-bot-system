# 停止済みデータの限定スナップショット

このツールは移行・変換ツールではない。明示した同一ディレクトリ直下の通常ファイルと SQLite のみを、新しい私有ディレクトリに保存し、検証後に別の新規ディレクトリへ元のファイル名で戻す。複数階層からなるデータ一式の移行には使えず、個々の取得も一貫した全体スナップショットにはならない。旧形式を一切変換しないため、対象アプリの新旧スキーマ互換性・新環境での意味的整合性や運用可能性は保証しない。何を対象とするか、変換方法や秘密を含めてよいかは運用者が別途判断する。サブディレクトリ、権限・所有者・時刻等のメタデータは復元しない。入力漏れは検出できない。出力には入力データと同じ秘密が入るため、バックアップ先の保管・暗号化・廃棄を管理する。ログは内容を出さない。

## 必須条件と制限

- **旧 Bot・関連サービス・export timer・全 writer を停止し、その停止を実行者が確認してから開始し、完了まで再開しない。** このツールだけでは停止や単一 writer、ファイル間の同時点整合性を保証できない。確認できない場合は実行しない。外部から変更するプロセス・攻撃者のいない信頼済みのホスト・ディレクトリで使用する。
- SQLite の非空 WAL または rollback journal がある場合は中止する。SHM はコピーしない。SQLite の正常終了後に WAL が残る場合、このツールでは扱えない。DB や WAL を消す・直接変更する指示ではない。安全な別途手順を検討する。SHM があっても元には触らない。
- パスのシンボリックリンク、入力のハードリンク、既存出力、同一・入れ子パスは拒否。出力の親は実行ユーザー所有かつ他ユーザーがアクセスできないディレクトリにする。出力は 0700、ファイルは 0600。実行ユーザーと root、同じユーザーの他プロセスからは守れない。
- SQLite のコピーを作ってから sqlite3 backup と integrity_check / foreign_key_check を実行し、入力は SQLite で開かず変更しない。非空 WAL や journal を無視して immutable モードを使ってはいけないので、複数回検査する。ファイルをコピー前後にハッシュし変更を検出するが、オンライン同時書込への対策にはならない。
- チェックサムは偶発的な破損の検知であり、マニフェストとデータを両方改ざんされた場合を防がない。強制終了や電源断で未完了ディレクトリが残ることがある（.incomplete が目印）。出力の耐電源断性は保証しない。手動で未完了ディレクトリを隔離し、新たな名前でやり直す。

## 手順（すべて例。実本番には適用前に別途検証）

1. 上記の全 writer と timer を停止し、停止状態を OS・サービス管理側で確認。実際のデータの一覧と型を別途確認し、必要最小限のみ選択。SQLite は必ず --sqlite、通常ファイルは --file。秘密を含む場合は出力への複製を承認し、私有親ディレクトリを用意する。
2. 入力を変更せず作成（入力と出力は別階層、出力は未存在）。複数のファイルは同じオプションを繰り返す。

   python3 tools/offline_snapshot.py create /private/legacy /private/snapshot --sqlite sample.db --file sample.json --offline-confirmed

3. python3 tools/offline_snapshot.py verify /private/snapshot が成功することを確認。ファイル一覧、ハッシュ、SQLite の整合性・外部キーを検査する。これだけでは業務データの正しさは保証しない。
4. 必要なら停止を維持したまま、別の未存在ディレクトリへ戻す。元ディレクトリへ上書きしない。

   python3 tools/offline_snapshot.py restore /private/snapshot /private/restored --offline-confirmed

5. 復元物を隔離環境でアプリ固有の検証にかける。旧形式の同名ファイルを取り出すだけであり、旧アプリと互換かの検証は別途必要。新環境の書込み後に旧形式へ逆変換する機能はない。運用切替・停止・再起動の判断は運用者が行う。

失敗時は出力を削除するが、強制終了の場合は削除できない。処理中も含め出力を信頼できない他者に書き換えさせない。通常ファイル扱いの SQLite ヘッダーは拒否するが、別形式の DB や暗号化 DB の自動判別はしない。
